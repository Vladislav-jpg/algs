## 1. Базовая теория: Графы «на пальцах»

### Что такое граф, вершины и рёбра
* **Граф** — это совокупность точек (**вершин**) и линий, которые их соединяют (**рёбер**).
  * Пример: станции метро — это вершины, а перегоны между ними — это рёбра.
* **Неориентированный граф** — рёбра двусторонние: если можно пройти от `0` к `1`, то точно так же можно пройти от `1` к `0`.
* **Степень вершины** — сколько рёбер прикреплено к этой вершине. Если у вершины 3 соседа, её степень равна 3.

---

### Способ 1: Матрица смежности (`int[][]`)
Это квадратная таблица размера $N \times N$ (где $N$ — число вершин).
* Строка — откуда идём, столбец — куда идём.
* `matrix[i][j] == 1` — между вершинами `i` и `j` есть ребро.
* `matrix[i][j] == 0` — ребра нет.

**Плюсы:** Мгновенная проверка наличия ребра за $O(1)$ (`if (matrix[u][v] == 1)`).  
**Минусы:** Занимает много памяти ($N^2$) и чтобы найти всех соседей вершины, нужно просмотреть всю строку из $N$ элементов.

---

### Способ 2: Списки смежности (`ArrayList<Integer>[]`)
Это массив, в каждой ячейке которого лежит обычный динамический список `ArrayList<Integer>`.
* `adjList[i]` хранит список номеров всех вершин, с которыми соединена вершина `i`.
* Например, если у вершины `0` соседи `1` и `5`, то в `adjList[0]` лежат числа `[1, 5]`.

**Плюсы:** Тратит память только на существующие рёбра. Перебор соседей происходит мгновенно — ровно столько итераций, сколько у вершины реальных соседей.

---

### Почему `ArrayList<Integer>[]`, а не `List<List<Integer>>`?
1. **Простота и производительность:** `ArrayList<Integer>[]` — это одномерный массив фиксированного размера $N$. Доступ к списку любой вершины `adjList[i]` происходит мгновенно по прямому индексу массива без лишней косвенной адресации интерфейсов.
2. **Академический стандарт:** В классических курсах алгоритмов (Седжвик, Кормен) граф задаётся именно как массив списков смежности. Вложенные интерфейсы `List<List<...>>` создают лишние накладные расходы на объекты-обертки и усложняют код.

## 2. Задание 1: Проверка наличия простого пути (Матрица смежности)

### Теория: Что такое простой путь?
* **Путь** — это последовательность вершин, соединенных рёбрами.
* **Простой путь** — путь, в котором **вершины не повторяются** (мы не заходим в одну и ту же вершину дважды).
* В графе простой путь между $u$ и $v$ существует тогда и только тогда, когда $v$ вообще достижима из $u$ (они находятся в одной связной части графа).
* Для поиска используем **DFS (Depth-First Search, поиск в глубину)** со **стеком (`Stack<Integer>`)**, в точности как в вашем `GraphDFS`.

### Код функции
```java
public static boolean hasSimplePath(int[][] matrix, int u, int v) {
    int n = matrix.length;
    if (u < 0 || u >= n || v < 0 || v >= n) {
        return false;
    }
    if (u == v) {
        return true;
    }

    boolean[] visited = new boolean[n];
    Stack<Integer> stack = new Stack<>();

    stack.push(u);

    while (!stack.isEmpty()) {
        int currentNode = stack.pop();

        if (currentNode == v) {
            return true;
        }

        if (!visited[currentNode]) {
            visited[currentNode] = true;

            for (int neighbor = 0; neighbor < n; neighbor++) {
                if (matrix[currentNode][neighbor] == 1 && !visited[neighbor]) {
                    stack.push(neighbor);
                }
            }
        }
    }

    return false;
}
```

### Построчное объяснение для защиты:
1. `int n = matrix.length;` — узнаём количество вершин в графе.
2. `if (u < 0 || u >= n || v < 0 || v >= n) return false;` — защита от дурака: если передали некорректный номер вершины (например, отрицательный или больше размера графа), возвращаем `false`.
3. `if (u == v) return true;` — если начальная и конечная вершины совпадают, путь тривиально существует (путь из самого себя в себя).
4. `boolean[] visited = new boolean[n];` — массив флажков. `visited[i] == true` означает, что в вершине `i` мы уже побывали. Это нужно, чтобы не зациклиться.
5. `Stack<Integer> stack = new Stack<>();` — стек для обхода в глубину (LIFO: последним пришел — первым ушел).
6. `stack.push(u);` — кладём начальную вершину $u$ на вершину стека.
7. `while (!stack.isEmpty())` — крутим цикл, пока в стеке есть хоть одна вершина для рассмотрения.
8. `int currentNode = stack.pop();` — достаём верхнюю вершину из стека.
9. `if (currentNode == v) return true;` — если вершина оказалась искомой $v$, значит, путь существует!
10. `if (!visited[currentNode])` — если мы ещё не были в этой вершине:
    * `visited[currentNode] = true;` — отмечаем её как посещенную;
    * `for (int neighbor = 0; neighbor < n; neighbor++)` — перебираем всех возможных соседей от $0$ до $N-1$;
    * `if (matrix[currentNode][neighbor] == 1 && !visited[neighbor])` — если ребро есть (`== 1`) и сосед ещё не посещён, кладём соседа в стек `stack.push(neighbor)`.
11. `return false;` — если стек опустел, а вершину $v$ мы так и не встретили, пути не существует.

## 3. Задание 2: Сохранение вершин простого пути в массиве

### Теория: Как восстановить путь?
Чтобы не просто сказать «да/нет», а записать сам путь `[0, 5, 9, 4]`, мы используем **поиск с возвратом (Backtracking)**:
1. Заходим в вершину, отмечаем её и добавляем в список пути `path.add(current)`.
2. Если дошли до цели — успех!
3. Если зашли в тупик — вычёркиваем вершину из текущего пути (`path.remove(path.size() - 1)`) и пробуем другую ветку.
4. В конце перекладываем список в обычный массив `int[]`, как в `GraphTasks` и `GraphDFS`.

### Код функции
```java
public static int[] findSimplePath(int[][] matrix, int u, int v) {
    int n = matrix.length;
    if (u < 0 || u >= n || v < 0 || v >= n) {
        return new int[0];
    }

    boolean[] visited = new boolean[n];
    List<Integer> path = new ArrayList<>();

    boolean found = dfsPath(matrix, u, v, visited, path);

    if (!found) {
        return new int[0];
    }

    // Перевод списка в массив
    int[] resultArray = new int[path.size()];
    for (int i = 0; i < path.size(); i++) {
        resultArray[i] = path.get(i);
    }

    return resultArray;
}

private static boolean dfsPath(int[][] matrix, int current, int target, boolean[] visited, List<Integer> path) {
    visited[current] = true;
    path.add(current);

    if (current == target) {
        return true;
    }

    for (int neighbor = 0; neighbor < matrix.length; neighbor++) {
        if (matrix[current][neighbor] == 1 && !visited[neighbor]) {
            if (dfsPath(matrix, neighbor, target, visited, path)) {
                return true;
            }
        }
    }

    path.remove(path.size() - 1); // Откат назад (backtracking)
    return false;
}
```

### Построчное объяснение для защиты:
1. `List<Integer> path = new ArrayList<>();` — динамический список, куда мы по очереди складываем вершины пути.
2. `boolean found = dfsPath(...)` — вызываем рекурсивный поиск.
3. Внутри `dfsPath`:
   * `visited[current] = true;` — помечаем, что зашли в текущую вершину.
   * `path.add(current);` — добавляем её в цепочку пути.
   * `if (current == target) return true;` — если мы в целевой вершине, выходим с успехом.
   * `for (int neighbor = 0; ...)` — смотрим каждого соседа. Если есть ребро и сосед не посещён, рекурсивно идём в него `dfsPath(...)`. Если тот вызов вернул `true`, передаём `true` выше по цепочке.
   * `path.remove(path.size() - 1);` — **ключевая строчка бэктрекинга!** Если ни один сосед не привёл к цели, удаляем текущую вершину из списка пути (шаг назад) и возвращаем `false`.
4. Перевод в массив:
   ```java
   int[] resultArray = new int[path.size()];
   for (int i = 0; i < path.size(); i++) {
       resultArray[i] = path.get(i);
   }
   ```
   Создаём массив размером ровно в длину пути и поэлементно переписываем в него числа. Если путь не найден — возвращаем пустой массив `new int[0]`.

## 4. Задание 3: Проверка наличия эйлерова цикла между двумя вершинами

### Теория: Что такое эйлеров цикл?
* **Эйлеров цикл** — это замкнутый маршрут, который проходит через **каждое ребро графа ровно один раз** и возвращается в начало. (Задача о Кенигсбергских мостах Леонарда Эйлера).
* **Критерий Эйлера (Теорема Эйлера):**
  Эйлеров цикл в неориентированном графе существует тогда и только тогда, когда:
  1. **Степень каждой вершины четная** ($0, 2, 4, 6 \dots$). Если в вершину вошли по ребру, из неё нужно выйти по другому ребру!
  2. **Все вершины с ребрами принадлежат одной компоненте связности** (между ними можно пройти, нет изолированных отдельных кусков с ребрами).
* **«Между двумя вершинами $u$ и $v$»:**
  Означает, что в графе существует эйлеров цикл, и этот цикл включает вершины $u$ и $v$ (то есть у $u$ и $v$ есть рёбра, и они находятся в этой связной компоненте).

### Код функции
```java
public static boolean hasEulerCycle(int[][] matrix, int u, int v) {
    int n = matrix.length;
    if (u < 0 || u >= n || v < 0 || v >= n) {
        return false;
    }

    int[] degrees = new int[n];
    int startNode = -1;

    // 1. Подсчет степеней вершин и проверка четности
    for (int i = 0; i < n; i++) {
        int degree = 0;
        for (int j = 0; j < n; j++) {
            if (matrix[i][j] == 1) {
                degree++;
            }
        }
        degrees[i] = degree;
        if (degree > 0) {
            startNode = i;
        }
        if (degree % 2 != 0) {
            return false; // Степень нечетная — эйлерова цикла нет
        }
    }

    if (startNode == -1) {
        return u == v; // В графе нет ребер вообще
    }

    if (degrees[u] == 0 || degrees[v] == 0) {
        return false; // У вершин u или v нет ребер
    }

    // 2. Проверка связности вершин ненулевой степени через DFS со стеком
    boolean[] visited = new boolean[n];
    Stack<Integer> stack = new Stack<>();
    stack.push(startNode);

    while (!stack.isEmpty()) {
        int currentNode = stack.pop();
        if (!visited[currentNode]) {
            visited[currentNode] = true;
            for (int neighbor = 0; neighbor < n; neighbor++) {
                if (matrix[currentNode][neighbor] == 1 && !visited[neighbor]) {
                    stack.push(neighbor);
                }
            }
        }
    }

    for (int i = 0; i < n; i++) {
        if (degrees[i] > 0 && !visited[i]) {
            return false;
        }
    }

    return visited[u] && visited[v];
}
```

### Построчное объяснение для защиты:
1. `int[] degrees = new int[n];` — массив для хранения степени каждой вершины.
2. Вложенный цикл `for` считает количество единиц в строке `matrix[i]` — это и есть степень вершины.
3. `if (degree % 2 != 0) return false;` — **главное свойство Эйлера!** Если остаток от деления на 2 не ноль (нечетное число), сразу возвращаем `false`.
4. `if (degrees[u] == 0 || degrees[v] == 0) return false;` — если вершина изолирована (степень 0), цикл через неё пройти не может.
5. Блок с `Stack<Integer> stack`: запускаем обычный DFS из любой вершины с ребрами `startNode`, чтобы обойти всю компоненту.
6. `for (int i = 0; i < n; i++) if (degrees[i] > 0 && !visited[i]) return false;` — если какая-то вершина с рёбрами осталась непосещенной, значит граф распадается на отдельные несвязанные куски, и общего эйлерова цикла быть не может.
7. `return visited[u] && visited[v];` — проверяем, что обе вершины $u$ и $v$ вошли в этот цикл.

## 5. Задание 4: Нахождение эйлерова цикла (Алгоритм Хирхольцера)

### Теория: Как работает алгоритм Хирхольцера?
Это самый эффективный и красивый алгоритм построения эйлерова цикла:
1. Берём вершину `startNode` и кладём в стек.
2. Смотрим на верхнюю вершину стека `stack.peek()`.
3. Если у неё есть непройденное ребро к соседу:
   * **Удаляем это ребро** (чтобы не пройти по нему второй раз)!
   * Кладём соседа в стек.
4. Если из текущей вершины ребер больше не осталось (тупик):
   * Снимаем вершину со стека `stack.pop()` и добавляем в список результата `circuit.add(...)`.
5. В конце переворачиваем список `Collections.reverse(circuit)` — получаем правильную последовательность обхода цикла.

### Код функции
```java
public static int[] findEulerCycle(int[][] matrix, int startNode) {
    int n = matrix.length;
    if (n == 0 || startNode < 0 || startNode >= n) {
        return new int[0];
    }

    if (!hasEulerCycle(matrix, startNode, startNode)) {
        return new int[0];
    }

    // Создаем копию матрицы, чтобы не портить исходный граф
    int[][] adj = new int[n][n];
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            adj[i][j] = matrix[i][j];
        }
    }

    Stack<Integer> stack = new Stack<>();
    List<Integer> circuit = new ArrayList<>();

    stack.push(startNode);

    while (!stack.isEmpty()) {
        int current = stack.peek(); // Смотрим на вершину, но пока не удаляем из стека
        int nextNeighbor = -1;

        for (int neighbor = 0; neighbor < n; neighbor++) {
            if (adj[current][neighbor] == 1) {
                nextNeighbor = neighbor;
                break;
            }
        }

        if (nextNeighbor != -1) {
            // Удаляем ребро в обе стороны (граф неориентированный)
            adj[current][nextNeighbor] = 0;
            adj[nextNeighbor][current] = 0;
            stack.push(nextNeighbor);
        } else {
            circuit.add(stack.pop());
        }
    }

    Collections.reverse(circuit);

    // Перевод списка в массив
    int[] resultArray = new int[circuit.size()];
    for (int i = 0; i < circuit.size(); i++) {
        resultArray[i] = circuit.get(i);
    }

    return resultArray;
}
```

### Построчное объяснение для защиты:
1. `if (!hasEulerCycle(matrix, startNode, startNode)) return new int[0];` — предварительно вызываем Задание 3. Если цикла нет, алгоритм даже не запускается.
2. `int[][] adj = new int[n][n]; ...` — **очень важный момент!** Мы создаем дубликат матрицы. Алгоритм в процессе работы стирает рёбра (`adj[i][j] = 0`). Если бы мы не сделали копию, мы бы сломали исходный граф пользователя.
3. `int current = stack.peek();` — подглядываем верхний элемент стека без его извлечения.
4. `adj[current][nextNeighbor] = 0; adj[nextNeighbor][current] = 0;` — когда шагнули по ребру, стираем его в матрице с обеих сторон.
5. `circuit.add(stack.pop());` — когда из вершины больше некуда идти, она заносится в итоговый список.
6. `Collections.reverse(circuit);` — так как вершины добавлялись с конца, разворачиваем порядок за $O(E)$.
7. Возвращаем заполненный `int[] resultArray`.

## 6. Задание 5: Наличие гамильтонова цикла между двумя вершинами

### Теория: В чём разница между Эйлеровым и Гамильтоновым циклом?
* **Эйлеров цикл** проходит через все **РЁБРА** ровно по одному разу.
* **Гамильтонов цикл** проходит через все **ВЕРШИНЫ** ровно по одному разу и возвращается в исходную.
* *Важно знать:* Простой математической формулы (критерия) для гамильтонова цикла нет — это известная **NP-полная задача**. Единственный способ её решить — полный перебор вариантов с возвратом (**Backtracking**).
* **«Между двумя вершинами $u$ и $v$»:**  
  Означает, что мы ищем гамильтонов путь длины $N$, начинающийся в $u$ и заканчивающийся в $v$, который закрывается ребром $(v, u)$, формируя полный гамильтонов цикл.

### Код функции
```java
public static boolean hasHamiltonianCycle(int[][] matrix, int u, int v) {
    int n = matrix.length;
    if (u < 0 || u >= n || v < 0 || v >= n || n < 3) {
        return false;
    }

    // Если между u и v нет прямого ребра, замкнуть цикл невозможно
    if (matrix[u][v] != 1) {
        return false;
    }

    boolean[] visited = new boolean[n];
    visited[u] = true;

    // Ищем путь длины n (посетить все n вершин) от u до v
    return dfsHamiltonian(matrix, u, v, 1, n, visited);
}

private static boolean dfsHamiltonian(int[][] matrix, int current, int targetEnd,
                                      int count, int totalVertices, boolean[] visited) {
    // Если обошли все n вершин: проверяем, оказались ли мы в v
    if (count == totalVertices) {
        return current == targetEnd;
    }

    for (int neighbor = 0; neighbor < totalVertices; neighbor++) {
        if (matrix[current][neighbor] == 1 && !visited[neighbor]) {
            visited[neighbor] = true; // Делаем шаг
            if (dfsHamiltonian(matrix, neighbor, targetEnd, count + 1, totalVertices, visited)) {
                return true;
            }
            visited[neighbor] = false; // Откат назад (backtracking)
        }
    }

    return false;
}
```

### Построчное объяснение для защиты:
1. `if (n < 3) return false;` — в цикле должно быть минимум 3 вершины (треугольник).
2. `if (matrix[u][v] != 1) return false;` — чтобы путь из $u$ в $v$ замкнулся в цикл, между $v$ и $u$ обязательно должно быть ребро.
3. `visited[u] = true;` — фиксируем начало в $u$.
4. Параметр `count` — счётчик, сколько вершин мы уже включили в цикл (стартуем с `count = 1`).
5. `if (count == totalVertices) return current == targetEnd;` — базовый случай: если мы посетили ровно $N$ вершин, проверяем, закончился ли наш обход в вершине $v$.
6. `visited[neighbor] = true; ... visited[neighbor] = false;` — классический backtracking: помечаем соседа посещенным, рекурсивно ищем дальше; если дальше путь построить не удалось — снимаем пометку (`false`) и даём шанс другим веткам.

## 7. Задание 6: Все алгоритмы на списках смежности (`ArrayList<Integer>[]`)

### Почему массив списков `ArrayList<Integer>[]` лучше матрицы?
В матрице смежности, чтобы найти соседей вершины `current`, мы вынуждены крутить цикл на $N$ итераций (`for (int neighbor = 0; neighbor < n; neighbor++)`), даже если у вершины всего 1 сосед.  
В списках смежности мы пишем:
```java
for (int neighbor : adjList[current])
```
Цикл выполнится ровно столько раз, сколько реальных соседей есть у вершины. Это работает намного быстрее на разреженных графах!

### Код вспомогательного метода (конвертация)
```java
@SuppressWarnings("unchecked")
public static ArrayList<Integer>[] matrixToAdjList(int[][] matrix) {
    int n = matrix.length;
    ArrayList<Integer>[] adjList = new ArrayList[n];

    for (int i = 0; i < n; i++) {
        adjList[i] = new ArrayList<>();
        for (int j = 0; j < n; j++) {
            if (matrix[i][j] == 1) {
                adjList[i].add(j);
            }
        }
    }

    return adjList;
}
```
**Объяснение:**
* Создаём массив `new ArrayList[n]`.
* В цикле инициализируем каждую ячейку новым пустым списком `adjList[i] = new ArrayList<>()`.
* Если в матрице стояла `1`, добавляем номер столбца `j` в список `adjList[i]`.

### Разбор алгоритмов на списках:
1. **`hasSimplePath(adjList, u, v)`**:  
   Логика полностью совпадает с Заданием 1, но вместо обхода строки матрицы соседи берутся через `for (int neighbor : adjList[currentNode])`.
2. **`findSimplePath(adjList, u, v)`**:  
   Рекурсивный обход со списками и откатом.
3. **`hasEulerCycle(adjList, u, v)`**:  
   Степень вершины находится мгновенно как длина списка: `int degree = adjList[i].size()`. Четность проверяется как `degree % 2 != 0`.
4. **`findEulerCycle(adjList, startNode)`**:  
   Делаем копию массива списков. Для удаления ребра `(current, next)` делаем:
   ```java
   int next = copy[current].remove(copy[current].size() - 1);
   copy[next].remove(Integer.valueOf(current));
   ```
5. **`hasHamiltonianCycle(adjList, u, v)`**:  
   Проверка наличия ребра: `if (!adjList[u].contains(v)) return false;`.

## 8. Шпаргалка к защите: Частые вопросы преподавателя и ответы

### Вопрос 1: В чём разница между простым путём и обычным путём?
> **Ответ:** В обычном пути вершины и рёбра могут повторяться (можно ходить туда-сюда и делать петли). В **простом пути** все вершины обязаны быть **различными** (каждую вершину посещаем максимум один раз).

### Вопрос 2: Чем принципиально отличаются Эйлеров и Гамильтонов циклы?
> **Ответ:**  
> * **Эйлеров цикл** проходит через все **рёбра** графа ровно по одному разу. Легко проверяется за время $O(V + E)$ по четности степеней.  
> * **Гамильтонов цикл** проходит через все **вершины** графа ровно по одному разу. Задача NP-полная, решается только перебором (backtracking) за экспоненциальное время.

### Вопрос 3: Зачем в коде пишется `path.remove(path.size() - 1)`?
> **Ответ:** Это шаг отката (backtracking). Если мы пошли по пути через текущую вершину и зашли в тупик (цель не найдена), мы должны удалить текущую вершину из списка пути, чтобы вернуться назад и попробовать обойти других соседей.

### Вопрос 4: Как работает проверка степеней для эйлерова цикла?
> **Ответ:** По теореме Эйлера, чтобы существовал замкнутый цикл по всем рёбрам, в каждую вершину нужно войти по одному ребру и выйти по другому. Значит, у каждой вершины число входящих/выходящих рёбер должно быть чётным: `degree % 2 == 0`. Если хотя бы у одной вершины степень нечётная — эйлерова цикла быть не может.

### Вопрос 5: Зачем в алгоритме Хирхольцера удалять рёбра?
> **Ответ:** Эйлеров цикл обязан пройти по каждому ребру **ровно один раз**. Удаляя пройденное ребро (`adj[u][v] = 0`), мы гарантируем, что алгоритм не пойдёт по этому ребру повторно.

### Вопрос 6: Почему стек разворачивается в конце алгоритма Хирхольцера (`Collections.reverse`)?
> **Ответ:** Вершины попадают в результирующий список `circuit` только тогда, когда из них больше нет неиспользованных рёбер (на фазе возврата из тупика). Поэтому они записываются с конца цикла к началу. Чтобы получить прямой порядок обхода от `startNode`, список нужно перевернуть.

### Вопрос 7: Когда выгоднее использовать матрицу смежности, а когда списки смежности?
> **Ответ:**  
> * **Матрица смежности** выгодна для **плотных** графов (где рёбер очень много, почти между всеми парами вершин), а также когда требуется мгновенно за $O(1)$ проверять наличие ребра между любыми $u$ и $v$.  
> * **Списки смежности** выгодны для **разреженных** графов (где рёбер немного): они экономят оперативную память ($O(V + E)$ вместо $O(V^2)$) и позволяют быстро перебирать только реальных соседей вершины.
